The component audit gets its checklists: `audit/components/<slug>.md` for each of the 104 component pages and `audit/pages/<kind>-<slug>.md` for the 24 patterns and templates, each with a generated facts block and variants table (one row per example, a tick cell per platform) merged by key so a reviewer's ticks and notes survive regeneration, and a hand-maintained rubric, family and specific checks, findings and sign-off seeded once from the plan. `bun run audit:checklists` writes them, `audit:checklists:check` (in CI and the pre-push hook) fails on a missing, orphaned or stale checklist and on any table row it cannot read, named by line, and `audit:status` counts ticks, open findings by severity and sign-offs, listing every row it could not count under the counts and exiting non-zero when there is one. Every audit table (variants, findings, sign-off, and the `PLATFORM-REFERENCES.md` catalog the facts read) goes through one escape-aware reader, so a `|` typed in a summary or a note stays in that cell and an empty cell typed `| |` no longer drops its row. The facts come from the repo's own records: tests and e2e count for a component when they import it from the kit, or for e2e when they drive the exact route of its docs page or of a hidden `/testing/*` page that renders it (a route in a comment, or `/components/button-group` for Button, no longer counts), and the touch-target and measure facts read identifiers in the component's TypeScript modules, never its markdown. Which builds look different per platform is now read per export with the TypeScript parser and fails safe: a platform part counts only when the export it injects diverges itself, and a namespace import, a helper function or a wrapped spread the reader cannot follow counts as the platform's own skin rather than the web build. The shells gate judges each imported export by that same read, and the docs' platform-skin registry drops the entries it proves are the web build: Avatar and AvatarGroup on both tables, Tabs on iOS, and MetricBreakdown on iOS, whose iOS Chip aliases the web skin (its markup is identical to the web build's in every scheme and surface). Repository tooling and docs only; nothing in the package changes.
