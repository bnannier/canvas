The component audit's signal reader follows a disabled value through the helper whose return brings it: a control given `...textEntryState({ disabled, readOnly })`, or `{...accessibility.field}` of `stepperAccessibility({ ..., disabled: !!disabled })`, reads the helper's parameters (object-destructured ones included, in the same module or imported) as the arguments the call gives them, so its `disabledBy` names the component's `disabled` prop exactly as the same value written on the tag does. Input's, Textarea's, Autocomplete's, InputOTP's and PhoneInput's fields and Stepper's helper-given field and group were read as disabled by nothing in particular, which the state coverage took as a control no example asks for; their Disabled examples now ask for them on every channel (`editable`, `aria-disabled`, `accessibilityState`), Autocomplete's explicit `{ ...entry.accessibilityState, expanded }` and PhoneInput's country segment (`!editable` of the helper's return) included. A parameter the reader cannot bind (a render helper read where it is written, a call that spreads its arguments) is marked unread instead, and the coverage fails on it rather than read the control as one no example asks for. Repository tooling and docs only; nothing in the package changes.
