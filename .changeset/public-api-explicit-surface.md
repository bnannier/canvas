The style foundation is now published through an explicit list, `src/style/public.ts`, instead of the kit's internal style hub, so a helper the kit adds for its own skins no longer becomes public by accident. The package exports the same 532 names with the same value and type bindings on the web, iOS and Android (a committed snapshot, `test/fixtures/public-api.json`, holds them). Every public component, part, hook, token and utility now carries a JSDoc summary in the published types; the web entries of Breadcrumb, the drag-and-drop parts and the Toast system export each member on its own so their summaries reach the declarations (the same objects as before). `bun run check:api` now also fails on a public value without a summary, stages every export with no docs page in `PENDING_DOCS` with the page planned for it (and fails once that page names it, or once the foundation reference exists while names are still staged), holds the materials manifest to the same docs routes (`check:materials` fails on a public foundation renderable with no route), counts a name that is an ordinary word only where a page shows it as code, compares each export's facts (value, component, callable, deprecated) across the iOS and Android resolutions, and ignores files npm never packs. No export is added, removed, renamed or deprecated.
