The component audit's web capture gains interaction states and pages. `bun run audit:web -- --states` hovers, focuses (with the Tab key), presses, opens, and finds invalid and disabled every component the interaction registry lists, through one recipe table that names each state's example, verifies the state from the page before photographing it (the hover's lift or wash, `:focus-visible` and the ring in the pixels on every side, the pressed style against the hovered one, a chart's value flag or readout under a press, the opened panel and where it painted, `aria-invalid`, `aria-disabled`), records a state it cannot confirm as not reached instead of photographing it, and measures each release (a press that should have been cancelled, an inspection or an overlay that does not clear become flags); overlays open from the web row and from the iOS and Android rows whose builds the docs inject, at every width, Tooltip and AvatarMenu among them. The table is held to each component's own source: a press, scrub, hover or field handler, the hover primitive or a pressed, hovered or focused look gives a state that needs a recipe or an exemption whose claim the unit test checks, and each checklist's facts gain an "Interaction states" row. `bun run audit:web -- --pages` photographs every pattern and template page's first screen and each of its sections with a margin for shadows, marked on the web by the docs page layout, and probes them; audit pages hold infinite loops still, so a spinner no longer starves parallel captures. Repository tooling and docs only; nothing in the package changes.
