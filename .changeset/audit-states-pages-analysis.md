The component audit captures interaction states and pages, and analyzes, sheets and indexes every capture. `bun run audit:web -- --states` hovers, focuses (with the Tab key), presses, opens, and finds invalid and disabled every component the interaction registry lists, through one recipe table that names each state's example, verifies the state from the page before photographing it (the hover's lift or wash, `:focus-visible` and the ring in the pixels on every side, the pressed style against the hovered one, a chart's value flag or readout under a press, the opened panel and where it painted, `aria-invalid`, `aria-disabled`), records a state it cannot confirm as not reached instead of photographing it, and measures each release (a press that should have been cancelled, an inspection or an overlay that does not clear become flags, named with what they mean in typed tables; a press is measured on the control pinned when it went down, so one that takes its control out of the page, as a dialog's Cancel does, is read rather than waited for, and a click that reaches the control as the button comes up after the pointer moved off counts as the press firing, since react-native-web runs `onPress` from that click, even when its handler changes nothing to see); overlays open from the web row and from the iOS and Android rows whose builds the docs inject, at every width (a drawer a component becomes only at and below a breakpoint, at those widths). The table is held to each component's own source, read statically: every press, scrub, resting-pointer handler, tab stop the web makes (every Pressable, a control role, `focusable`) and overlay it renders or opens, whether written on the element or spread onto it from a value the reader can follow, needs a recipe or an exemption whose claim is checked against that source and the page; a spread it cannot follow gives nothing. A state is checked as a whole, not per element, except the overlays a component opens: each one its source renders, or hands its open state to (AvatarMenu's Dropdown, a part its platform entries inject, included), needs a recipe, and a component whose source renders more than one (the Calendar's hover card and day peek) has each recipe that opens one name it, so one overlay's recipe cannot stand in for another's. A raw primitive's rail examples are read the same way, spreads included. Each checklist's facts gain an "Interaction states" row. `bun run audit:web -- --pages` photographs every pattern and template page's first screen and each of its sections, and probes them; audit pages hold infinite loops still. Every probed region records where its boxes sit in the viewport and every text the opacity that dims its ink apart from the groups it shares with its backdrop, so the analysis can find each text in its photograph. `bun run audit:analyze` reads variant cards, state shots and page sections the same way: contrast from the DOM where it resolved, and otherwise the text's painted ink over the background read from the photograph (with the colour behind a dimmed group read around it), fail-likely under 4.0 of 4.5 and review up to 4.5; type floors, small targets per region, the tree held identical across looks and surfaces, a state's own and release flags, and a state not reached with its reason. `bun run audit:calibrate` measures the photograph readings against the DOM over every family. `bun run audit:sheets` lays out per variant the card, row, device and comparison sheets, per component its states (desktop first, each tile its photograph with its flags) and per page its first screen across widths and looks, every sheet within 1600 px and cut into numbered sheets where a grid would be unreadable. `bun run audit:index` builds `.audit/current/` from the newest capture of each cell across every run, with an index per component (its cells, its states table) and per page (its cells, its sections linked one by one), and a summary ranked by flags with every state not reached and every release flag; `bun run audit:prune` deletes old runs while keeping the newest two captures of every cell, then rebuilds the index so none of its links points at a deleted run. Nothing in the package changes. In the docs, the pattern and template pages wrap each section in one more View, which carries its `data-mockup-section` key on the web for the page capture; the pages look as they did.
