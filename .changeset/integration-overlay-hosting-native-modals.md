The Integration page documents overlay hosting and the Modal blur bridge (audit K12-5). A new Overlay hosting section presents `OverlayProvider` at the app's root, filling the window, and on Android with `@nannier/canvas-blur` the capture plane its page becomes. Its Native modals part presents `GlassModalBlurTarget` for an app hosting its own React Native `Modal`, with a kit-only example in Drawer's order (the bridge, then `OverlayProvider separateWindow`, then the content), the Android preconditions, the no-op platforms, the rule that it belongs only inside a Modal (in the main window its surfaces keep their solid skin), what an Android Modal's frost samples (the outermost provider's page only, not the toasts, a Modal beneath or its own scrim, while iOS and the web blur the whole stack; the owner's GMBT-3 decision), and an accessibility note. The README's custom-Modal recipe and Android blur paragraph name the bridge, which they had left out, so an app that followed them got solid Modal panels on Android. The public API manifest documents `GlassModalBlurTarget` and `OverlayProvider` there and the materials inventory gives both the route; `OverlayProviderProps` and `OverlayViewportInsets` stay staged for OverlayProvider's turn. Docs only; nothing in the package changes.
