`DataTable` takes a new `stacks` option (with `stackBreakpoint`, default `sm`), the minor's user-visible capability: when the table's own container is at or below the breakpoint, each row lays its cells out top to bottom at the full width instead of side by side, so long text reads at the table's width rather than a column's share of it. The first cell leads the row as its title and every later cell sits under its column label, set in a new small muted label type per platform (the kit's caption role on the web, Material 3 label-small on Android, Caption 2 on iOS). The header row stays only while it holds a control (a sortable column, or the box that selects every row), as a wrapping band of its labels; the selection box and the row actions keep their places. A stacked table never pans, and on iOS it stacks instead of collapsing to its first column. Like `Row stacks` it is measured against its own container, seeded from the window on the first frame, and crossing the breakpoint changes only the layout: rows, stateful cells and an open editor stay mounted. Without `stacks` nothing changes. The docs' prop tables use it, so on a phone every prop's description now reads under its name and type, on iOS too, where the table used to show only the prop names.
